# iphost v0.4.0 planned changes

We add three opt-in features:

- `custom`: Enable the crate consumer to specify an alternative resolver's IP address (and optionally the bind interface or VRF). Uses [hickory-resolver](https://crates.io/crates/hickory-resolver) as the DNS stack (optional dependency, pulled in only by this feature).
- `ra`: listens for v6 RA DNS settings (RDNSS/DNSSL) on an interface, on a raw ICMPv6 socket when privileged, falling back to a netlink socket on Linux. **Depends on `custom`**.
- `dhcpv6`: we do DHCPv6 Information-Request ourselves on the configured interface, and use that resolver set. **Depends on `custom`**.

## Portability

- POSIX-like platforms (Linux, macOS, FreeBSD) are supported. Interface names are resolved into interface indexes (`if_nametoindex`) on non-Linux supported platforms.
- Linux-kernel-specific facilities (netlink, `SO_BINDTODEVICE`, VRF) are gated on `target_os = "linux"`.

## `ra` details

- RA DNS settings cannot be queried, only listened for as each RA arrives.
- Preferred path (with the necessary privileges, e.g. `CAP_NET_RAW` on Linux): we open a raw ICMPv6 socket ourselves (`ICMP6_FILTER` for RA, RFC 3542 API, portable to all supported platforms), parse RAs directly, and emit Router Solicitations to speed things up. This works even when the kernel does not process RAs (`accept_ra=0`, as is typical when systemd-networkd handles RAs itself).
  - Received RAs MUST be validated per RFC 4861 (hop limit 255 via `IPV6_RECVHOPLIMIT`, link-local source).
- Fallback (unprivileged, Linux only): a netlink socket on `RTNLGRP_ND_USEROPT` (`RTM_NEWNDUSEROPT`). This only delivers settings when the kernel itself processes RAs on the interface (`accept_ra` enabled), and we wait for the next unsolicited RA.
- Without privileges on non-Linux platforms, `ra` is unavailable (runtime error).
- Newly arrived RA DNS settings overwrite the previous values.
- RDNSS/DNSSL lifetimes (RFC 8106) MUST be tracked; a lifetime of 0 withdraws the entry. Expired (stale) resolvers MAY still be used while no new values are available.

## `dhcpv6` details

- The client must bind UDP port 546, which requires root or `CAP_NET_BIND_SERVICE` on Linux (privileged port on other POSIX platforms, too).

## hickory-resolver notes

- `ConnectionConfig::bind_addr` only sets a local `SocketAddr`; interface/VRF binding (`SO_BINDTODEVICE`) needs a custom `RuntimeProvider` that creates the sockets.
- `NameServerConfig::ip` is a plain `IpAddr` with no scope ID, so link-local resolvers (possible with RDNSS/DHCPv6) also need the interface-bound sockets from the custom `RuntimeProvider`.

## `Resolver` enum

**Non-exhaustive**.

- `Resolver::System`
- `Resolver::Static(StaticResolverConfig)` (feature `custom`)
- `Resolver::Ra(RaResolverConfig)` (feature `ra`)
- `Resolver::Dhcpv6(Dhcpv6ResolverConfig)` (feature `dhcpv6`)

Swapping `Resolver`s in runtime MUST be supported (not configured-once).

`.with_resolver()` constructor or such should be added to explicitly set the resolver, in addition to runtime-change methods.
